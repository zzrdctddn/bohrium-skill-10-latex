# RLBD 方法细则与反例库

## 四机制关系
RLBD 把"写完能编过"拆成四道可分别验收的关卡：诊断树解决"错在哪、为什么"，公式表格规则解决"改得对不对"，可编辑交付解决"交出去能不能用"，清单与收敛解决"别人能不能复现"。

## 编译得通：错误诊断树的使用法
1. **先探测**：确认引擎与发行版；无引擎切静态诊断，禁止编造运行日志。
2. **再分类**：`missing_package` / `file_not_found` / `syntax` / `math` / `table` / `reference` / `font` / `cascade`。
3. **后定位**：每条错误写清文件、行号、根因、修复建议；`cascade=true` 的错误归并到首个根因，先修根因。
4. **闭环**：每改一处重编译验证；直到无新增错误或确认受阻材料。日志原文片段保留供复核。

## 改得对：公式与表格的验收口径
- 公式：符号正斜体与含义一致（变量斜体、算子/单位正体）、编号连续、`\label` 紧随编号环境、多行对齐按关系符对齐；正文引用号与公式号一致。
- 表格：列宽与列格式匹配内容、数值按小数点对齐、三线表样式符合模板、跨页用长表环境；禁止用 `\scalebox`/`\resizebox` 掩盖溢出。
- 版式与模板：必填项（标题、作者、基金、日期、分类等）逐项对照，未知写"待确认"；合原文意图又不违反模板约束。

## 交得可用：可编辑交付的三条底线
1. 交付 `.tex` 源码工程（主文件/子文件、导言区、`.bib`、模板类文件、素材路径），可继续编辑维护。
2. 保留改动前后对照 diff 与 `change_log`，可回溯。
3. 不把 PDF、截图、不可编译的孤立片段当最终产物；预览文件仅作辅助。

## 复现得了：收敛与清单
- 收敛程序：`latex → bibtex → latex ×2`（模板另有规定从其规定）；判据为无 `undefined references/citations` 且 `.aux` 稳定。
- 清单字段：发行版与版本、模板版本、宏包与字体版本、编译命令与轮次、素材路径；均注明来源，未知写"待确认"。
- 无引擎时：`convergence.converged=unknown`，只给"预期轮次与检查项"，不声称收敛。

## 反例库
| 反例 | 为什么错 | 改法 |
|---|---|---|
| 看到第一条报错就停，声称"编译失败无法修" | 错误常级联，首条未必根因 | 读完整日志，按诊断树分类归并到根因 |
| 无引擎却写 `exit code 0, 编译通过` | 编造编译事实 | `available=false`，`converged=unknown`，静态诊断 |
| 逐条瞎改级联错误 | 修一个冒出三个 | 修首个根因后重编译，级联自动消失 |
| 表格溢出用 `scalebox` 缩小 | 掩盖问题、字号变小不可读 | 调列宽/列格式或拆表/长表 |
| 公式符号与正文叙述不一致 | 含义错，评审会质疑 | 按符号规则对齐正文与公式 |
| `\ref` 显示 `??` 就改正文编号硬写 | 多遍未收敛，硬写会错乱 | 检查 `\label` 位置，按多遍程序编译至收敛 |
| 把 PDF 当交付物 | 不可编辑维护 | 交付 `.tex` 源码工程与清单 |
| 清单里编造宏包版本号 | 他人无法复现 | 未知写"待确认"并追问 |
| 模板必填项随便填日期/作者 | 编造元数据 | 标"待确认"进人工确认 |

## 诊断与核对分离
诊断改码阶段只管定位与修复；完成后以"审阅者"身份独立执行 `checklist.md`，核验是否真按规则改、交付是否可编辑、清单是否可复现、有无编造，必要时回改并写 `change_log`。两遍不可合并。
